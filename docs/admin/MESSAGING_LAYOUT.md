# Messaging scrolling and adjustable admin navigation

The admin Messages page now fits the actual space below its header rather than assigning a viewport-sized child to a non-flex tab container. A MessagingViewport measures the available height, accounts for surrounding bottom padding, and responds to layout, window and visual-viewport changes. The mobile conversation overlay also uses the visual viewport height/offset for keyboard changes.

The chat tab root/panels/workspaces propagate min-height:0 and constrained flex sizing. Conversation lists and message histories are separately focusable native scrolling regions. Search and chat headings remain above their lists, and the reply composer does not shrink into the scroll area. Long tabs can scroll horizontally on narrow screens; Insights has its own vertical overflow. Messages uses the existing toolbar Back control; the mobile conversation Back returns to the conversation list.

Message scroll listeners now attach when a conversation finishes loading, not only on the first loading render. Incoming messages preserve the user's position while they read older messages; switching conversations and remaining near the bottom retain the existing latest-message behaviour. No message payload, recipients, sending logic or access policies changed.

The admin sidebar is sticky, viewport height and independently scrollable. Its header, collapse control and account/logout footer remain reachable. The desktop resize handle is on the right edge below the collapse button, which keeps the two controls from intercepting each other. Drag it or focus it and use Left/Right (16 px), Home (240 px), End (420 px), or double-click to restore 288 px. Expanded width is stored as an optional local device preference. Collapse keeps the remembered expanded width. Mobile uses the existing navigation drawer with a constrained scrolling menu and no resize handle.

Validation: tests cover keyboard bounds/persistence/reset, viewport sizing/cleanup and simulated mobile visual-viewport changes, late-loading scroll listener attachment and preservation of older-message reading. Existing Messages and admin navigation tests remain in place. Local browser checks mounted actual admin layout, message hooks and UI against 100 sample conversations and 80 sample messages, reached the final conversation and last menu item independently, verified pointer resizing and collapse/expand, and checked a 390×844 phone viewport. The desktop document matched its 688 px viewport, reply Send bottom was 587 px; on the phone Send bottom was 832 px within 844 px, with 390 px document width. The physical mobile soft keyboard was not opened; its viewport events are covered in component tests. No messages were sent and no live student data was used or changed.
